# OpenConnect Native

Бесплатное нативное приложение macOS для VPN, совместимых с Cisco AnyConnect.
Оно включает OpenConnect внутри DMG: пользователю не нужны Homebrew, Terminal
или отдельная установка VPN-клиента.

По умолчанию приложение показывает обычное компактное окно, значок в Dock и
фирменный значок в строке меню macOS. Через шестерёнку можно включить режим
«Только строка меню»; окно и Dock тогда скрываются. Цвет самой пиктограммы
показывает состояние VPN: серый — отключено, жёлтый — идёт подключение,
зелёный — подключено, красный — соединение оборвалось с ошибкой.

OpenConnect Native — независимый проект. Он не связан с Cisco Systems и не
является официальным приложением проекта OpenConnect. Названия Cisco и
AnyConnect используются только для описания совместимости.

## Как работает

- GUI сохраняет шлюз, группу и логин в `UserDefaults`, основной пароль — в
  Keychain, а OTP держит только в памяти одной попытки;
- при первом подключении приложение один раз устанавливает root-owned helper и
  LaunchDaemon. После этого подключение и отключение больше не запрашивают
  пароль администратора;
- приложение общается с helper по XPC. Helper принимает команды только от
  конкретной подписанной копии приложения, которая его установила;
- встроенный helper работает напрямую с `libopenconnect`; консольный клиент не
  запускается и пользователю не устанавливается;
- первая попытка читает `authgroup_opt`, не отправляя пароль, и возвращает GUI
  список групп. Выбранная группа сохраняется в профиле;
- кнопка обновления рядом с полем «Группа» повторно получает актуальные группы
  без отправки пароля и без запуска попытки VPN-подключения;
- пароль передаётся helper через одноразовый plist с правами `0600`, удаляемый
  сразу после чтения. OTP передаётся только после реального challenge и нигде
  не сохраняется;
- правила защиты от повторных ошибок соответствуют Project Pulse: 1 минута
  после первой и 30 минут после второй ошибки за 30 минут. Одна попытка не
  может повторно отправить пароль или OTP; автоматического повтора нет;
- таймаут ответа шлюза — 45 секунд, таймаут ввода OTP — 60 секунд. После
  успешной авторизации этот таймер отключается и больше не может разорвать
  установленный туннель;
- после авторизации OpenConnect до пяти минут восстанавливает транспорт при
  кратковременном сетевом сбое. GUI продолжает контролировать helper всё время
  соединения и показывает причину, если восстановить VPN не удалось;
- статус «Подключено» появляется только после того, как macOS применила
  выданный VPN-адрес, корпоративные DNS-серверы и все split-DNS-домены;
- DNS применяется нативно только к интерфейсу OpenConnect: приложение не
  изменяет DNS Wi-Fi и других одновременно работающих VPN. Все домены из
  `CISCO_SPLIT_DNS` получают отдельное правило macOS Supplemental Match Domain;
- если шлюз передал срок авторизации, helper получает его через
  `openconnect_get_auth_expiration()`, а компактная строка состояния показывает
  оставшееся время. За 15 и 5 минут macOS предупреждает о завершении сеанса;
- истечение серверного срока отображается отдельно как «Сеанс завершён», не
  считается ошибкой пароля и не запускает защитную блокировку повторных попыток;
- серверный idle-timeout показывается в сведениях о подключении. Если шлюз не
  передал срок или таймаут, соответствующая строка не отображается;
- строка статуса открывает в том же окне компактную сводку: транспорт
  DTLS/TLS, шифрование, фактический шлюз, интерфейс, MTU, трафик, срок сеанса
  и режим маршрутизации. Отдельные вложенные страницы показывают маршруты,
  DNS/WINS, Proxy PAC и отпечаток сертификата;
- helper запрашивает у `libopenconnect` счётчики трафика раз в секунду и
  передаёт GUI только безопасный белый список параметров. Cookie, пароль,
  OTP и необработанные серверные заголовки в диагностический снимок не входят;
- цветная иконка приложения используется как ненавязчивый фон справа сверху,
  в духе компактного окна Cisco AnyConnect. Все сведения остаются в памяти и
  не сохраняются на диск.
- меню в строке macOS открывается системным `NSPopover`: небольшая нативная
  стрелка точно указывает на цветной значок приложения и перемещается вместе с ним.
- системный зелёный используется как единый акцент интерфейса: для основной
  кнопки, фокуса полей, Picker и навигации по сведениям.
- во время установления VPN-соединения строка статуса показывает компактную
  анимацию пинг-понга; при включённом «Уменьшении движения» она остаётся статичной.
- версия privileged helper отделена от версии GUI, поэтому обновления цвета и
  компоновки больше не вызывают лишний запрос пароля администратора.
- при первом обращении к остановленному LaunchDaemon приложение ждёт готовности
  XPC listener и повторяет только локальный `ping`; временная задержка запуска
  больше не открывает ошибочно окно переустановки через `osascript`.
- установщик после `bootout` дожидается удаления старой регистрации launchd,
  выполняет `bootstrap` новой службы и отдельно проверяет, что она появилась.

Поддерживаются логин/пароль, обнаружение и запоминание групп, а также live OTP.
SAML/SSO в браузере, CSD/HostScan и клиентские сертификаты требуют отдельной
работы.

## Установка из GitHub Release

1. Скачайте `OpenConnect-Native-*.dmg` и файл `*.dmg.sha256`.
2. В Terminal выполните `shasum -a 256 OpenConnect-Native-*.dmg` и сравните хеш с
   файлом `.sha256`.
3. Откройте DMG и перетащите `OpenConnect Native.app` в `Applications`.
4. При первом запуске нажмите приложение правой кнопкой → **Открыть** →
   **Открыть**. Это одноразовое требование Gatekeeper для бесплатной ad-hoc
   подписи.
5. Нажмите фирменный значок в строке меню. В компактном окне заполните поля
   «Шлюз», «Логин» и «Пароль», затем нажмите «Подключиться». Полученная от
   сервера группа появится там же. Пароль будет сохранён в Keychain после
   успешного подключения.
6. При первом подключении подтвердите единственную установку системного
   компонента. В дальнейшем для VPN потребуется только OTP от сервера.

При первом запуске обычное окно объяснит, где находится цветной значок строки
меню. Переключатель режима расположен в шестерёнке → «Только строка меню».

## Полное удаление

Перетаскивание приложения в Корзину само по себе не может запускать команды от
root — это ограничение macOS. Поэтому перед удалением откройте шестерёнку в
приложении и нажмите **«Удалить системный компонент…»**. Приложение отключит VPN
и после одного подтверждения администратора удалит только эти объекты:

```text
/Library/PrivilegedHelperTools/com.max.openconnectnative.runtime
/Library/LaunchDaemons/com.max.openconnectnative.helper.plist
```

После этого приложение можно переместить в Корзину. LaunchDaemon, helper,
встроенные библиотеки и root-права приложения в системе не останутся.

## Локальная сборка DMG

Требуются macOS 14+, Xcode 15.4+, Homebrew и OpenConnect:

```bash
brew install xcodegen openconnect
cd /Users/max/Downloads/CiscoConnect
./Scripts/package_dmg.sh local
```

Готовые файлы всегда находятся только в папке `Releases`:

```bash
Releases/OpenConnect-Native-0.7.6.dmg
Releases/OpenConnect-Native-0.7.6.dmg.sha256
```

Папка `build` используется только во время сборки и удаляется автоматически.
После каждой сборки в `Releases` остаются только две последние версии DMG и
их SHA-256. Более старые локальные артефакты удаляются автоматически.
Скрипт компилирует helper, вкладывает `libopenconnect` и динамические библиотеки,
подписывает компоненты, монтирует готовый DMG для проверки и только затем
помещает результат в `Releases`.

Режим `local` автоматически использует бесплатный сертификат Apple Development
из Xcode. После однократного обновления системного компонента его доверие к
приложению сохраняется между локальными сборками, поэтому GUI-обновления не
вызывают новый запрос `osascript`. Для воспроизводимой публичной GitHub-сборки
workflow использует `development` с ad-hoc подписью; такая сборка после каждого
обновления один раз обновляет точный CDHash в helper.

## Публикация на GitHub

Workflow [`.github/workflows/release.yml`](.github/workflows/release.yml)
собирает DMG на macOS 14. Pull request публикует артефакт проверки, а тег вида
`v0.7.6` создаёт GitHub Release с DMG и SHA-256:

```bash
git tag v0.7.6
git push origin v0.7.6
```

После публикации workflow сохраняет только два последних GitHub Release.
Старые записи Release и их файлы удаляются, а Git-теги остаются в репозитории.

Никакой Apple Developer Program для этого не нужен. Однако ad-hoc подпись не
является Developer ID: приложение не будет нотарифицировано и при первом
запуске потребует ручного разрешения Gatekeeper. Убрать это предупреждение для
всех пользователей можно только с платным Apple Developer Program и Developer
ID Application certificate.

## Структура

```text
Sources/CiscoConnect/
├── App/             # запуск и композиция зависимостей
├── Domain/          # профиль, статусы, Cisco-формы
├── Persistence/     # UserDefaults, Keychain, cooldown
├── Services/        # use case VPN и защищённый запуск OpenConnect
└── UI/              # системные SwiftUI-экраны macOS
App/Brand/            # PNG-превью фирменной иконки
App/Resources/        # собранная ICNS-иконка приложения
Scripts/             # XcodeGen, упаковка runtime и DMG
Releases/            # единственное место с готовыми DMG и SHA-256
Helper/              # привилегированный libopenconnect-движок и auth forms
.github/workflows/   # CI и GitHub Releases
Tests/               # доменные правила
```

Проверка доменной логики: `swift test`. Проверка хранения двух последних
релизов: `./Tests/ReleasePipelineTests.sh`. Упаковочный pipeline также проверяет,
что одноразовый IPC-запрос удаляется, а состояние privileged helper доступно GUI.
